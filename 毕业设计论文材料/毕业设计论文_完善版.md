# 基于 Spring Boot 的房屋交易平台设计与实现

## 摘要

随着互联网房产服务逐步从信息展示走向交易协同，用户对房源检索效率、业务闭环能力和交互体验提出了更高要求。传统房产平台往往只强调房源展示，缺少围绕用户找房、咨询、预约、支付和售后服务的一体化支撑，导致信息分散、沟通成本较高、业务流程割裂。针对上述问题，本文结合毕业设计项目，设计并实现了一套基于 Spring Boot 的房屋交易平台。系统采用前后端分离模式，前端使用 Vue3、Vite 与 Element Plus 构建交互界面，后端采用 Spring Boot、Spring Security、JWT 和 Spring Data JPA 实现业务服务与权限控制，数据库使用 MySQL 8 完成业务数据持久化。

本文从系统需求分析、概要设计、详细设计与实现、系统测试等方面对项目进行了完整阐述。系统围绕普通用户、经纪人和管理员三类角色展开设计，实现了用户注册登录、房源发布与审核、房源检索与筛选、收藏与浏览记录、在线咨询、预约看房、意向金支付、价格提醒、评价反馈、客服工单、后台统计等功能模块。同时，平台还集成了地图找房、个性化推荐、3D 看房和软装工作室等扩展模块。测试结果表明，系统主要业务流程能够稳定运行，功能逻辑较为完整，能够满足毕业设计场景下的应用需求。

**关键词：** 房屋交易平台；Spring Boot；Vue3；前后端分离；预约看房；个性化推荐

## Abstract

With the rapid development of Internet-based real estate services shifting from information display to transaction collaboration, users have raised higher demands on property search efficiency, end-to-end business process support, and interactive experience. Traditional real estate platforms tend to focus only on listing presentation, lacking integrated support for the complete user journey including consultation, appointment scheduling, payment, and after-sales service.

To address these challenges, this thesis designs and implements a housing transaction platform based on Spring Boot. The system adopts a front-end and back-end separation architecture. The front end is built with Vue3, Vite, and Element Plus, while the back end leverages Spring Boot, Spring Security, JWT, and Spring Data JPA. MySQL 8 is used for persistent storage.

The system is designed around three user roles—regular users, agents, and administrators—and implements modules including user authentication, property management, appointment scheduling, online consultation, payment processing, price alerts, reviews, support tickets, and data analytics. Extension modules including map-based search, personalized recommendation, 3D property viewing, and furnishing studio are also integrated. Test results confirm that the main business workflows operate stably and the functional logic is substantially complete.

**Keywords:** Housing Transaction Platform; Spring Boot; Vue3; Front-Back Separation; Appointment Scheduling; Personalized Recommendation

## 第一章 绪论

### 1.1 研究背景

随着城市化进程不断推进，住房租售需求逐步走向线上化、平台化与精细化。用户在找房过程中不再满足于简单浏览房源信息，而更加关注筛选效率、看房流程是否顺畅、沟通是否及时以及交易过程是否安全可靠。传统线下房产服务依赖人工沟通与线下协调，效率较低；部分线上平台虽然提供房源信息展示，但在预约、支付、评价和售后处理等环节仍缺少统一支撑，导致用户体验不连续。

从工程实践角度来看，房屋交易平台具有较强的综合性。它既包含用户认证、数据管理、权限控制等典型信息系统问题，也涉及预约调度、支付状态流转、消息沟通、统计分析和推荐服务等较复杂的业务逻辑。因此，以房屋交易平台为研究对象，不仅能够训练完整的软件工程能力，也具有较好的现实应用价值。

### 1.2 研究目的与意义

本课题的主要目标是设计并实现一个结构清晰、功能完整、能够运行演示的房屋交易平台，使其覆盖用户从浏览房源到预约交易的主要流程，并体现毕业设计在需求分析、架构设计、编码实现、测试验证和论文撰写等方面的综合训练成果。

本研究的意义主要体现在三个方面。第一，在应用层面，通过将房源管理、预约看房、在线咨询、订单支付和售后服务整合到同一平台中，可以有效降低房产交易的沟通成本，提高业务协同效率。第二，在工程层面，基于前后端分离架构和主流开发框架构建系统，有利于提高系统的可维护性与扩展性，为后续工程化演进提供良好基础。第三，在教学层面，本项目完整覆盖了软件工程的需求分析、系统设计、编码实现和测试验证等主要阶段，具有较强的课程实践与毕业设计示范意义。

### 1.3 国内外研究现状

国内互联网房产服务平台的发展较早，以链家、安居客、贝壳找房为代表的主流平台在房源信息展示、经纪人管理和交易辅助等方面积累了丰富经验。随着 Spring Boot、Vue 等开发框架的普及，越来越多的研究与实践项目开始采用前后端分离模式构建房产、电商等业务系统。这类研究通常强调系统的模块划分、权限控制和数据库设计，适合作为教学型系统建设参考。但从毕业设计常见成果来看，很多系统停留在基础增删改查层面，对于预约流转、支付状态联动和推荐增强等扩展能力考虑不足。

国外相关平台如 Zillow、Realtor.com 等更强调数据驱动和用户体验优化，通过智能推荐、地图检索、虚拟看房和多终端同步提升用户决策效率。这些系统在个性化服务、业务闭环设计和可视化体验上的思路，为本课题提供了参考。

综合来看，当前教学类房产系统在基础功能实现方面较为成熟，但在多角色协同、流程闭环和展示亮点方面仍有提升空间。本文在常规房屋交易平台基础上，引入推荐、地图、3D 看房和软装展示等扩展功能，以增强系统的完整性与答辩展示效果。

## 第二章 相关技术简介

### 2.1 Vue3 与 Vite

Vue3 是当前前端开发中应用广泛的渐进式 JavaScript 框架，具备组件化开发、响应式数据绑定（Composition API）和较强的生态兼容性。相比 Vue2，Vue3 通过 Proxy 实现更高效的响应式系统，并支持 Tree-shaking 减小打包体积。对于本系统而言，Vue3 可以较好地支撑首页、房源列表、详情页、后台页面等多视图场景，结合 Vue Router 实现单页应用路由管理，结合 Pinia 实现全局状态管理。

Vite 作为现代化前端构建工具，基于原生 ES Module 实现按需编译，具有启动速度快、热更新响应迅速等优点，能够显著提升开发阶段的调试效率，是目前 Vue3 项目的主流构建工具选择。

### 2.2 Element Plus、ECharts 与 Leaflet

Element Plus 是专为 Vue3 设计的桌面端 UI 组件库，提供了覆盖表单、表格、弹窗、标签页、布局容器等场景的丰富组件。本系统中的登录注册、房源表单、预约弹窗、后台管理界面等均依赖该组件库实现。

ECharts 是百度开源的前端可视化图表库，支持折线图、柱状图、饼图、漏斗图等多种图表类型。本系统在后台统计模块中使用 ECharts 渲染管理员与经纪人的数据看板，帮助用户直观了解房源状态分布、订单转化率和近七日活跃趋势等指标。

Leaflet 是轻量级的开源地图 JavaScript 库，支持基于经纬度坐标的交互式地图展示。本系统的地图找房模块使用 Leaflet 配合 OpenStreetMap 底图，实现房源在地图上的空间定位与可视化展示，辅助用户进行位置决策。

### 2.3 Spring Boot

Spring Boot 是基于 Spring 生态构建的快速开发框架，通过自动配置机制和内嵌 Tomcat 容器，极大简化了 Java Web 项目的搭建与部署过程。Spring Boot 遵循"约定优于配置"原则，利用其分层架构（Controller → Service → Repository）组织业务代码，同时借助 Maven 进行依赖管理。与传统 Java Web 开发相比，Spring Boot 更适合毕业设计这类强调开发效率和模块整合的项目场景。

### 2.4 Spring Security 与 JWT

Spring Security 是 Spring 生态中功能完善的安全框架，提供了认证、授权、CSRF 防护和 Session 管理等机制，支持基于角色的访问控制（RBAC）。

JWT（JSON Web Token）是开放标准（RFC 7519），能够以无状态方式在服务端和客户端之间安全传递身份声明。本系统在用户登录成功后签发 JWT 令牌，前端在后续请求的 Authorization Header 中携带令牌，后端通过 JwtAuthTokenFilter 解析令牌完成身份校验，实现普通用户、经纪人和管理员三类角色的分级访问控制，无需维护服务端会话状态。

### 2.5 Spring Data JPA 与 MySQL

Spring Data JPA 基于 JPA 规范，通过 Hibernate 提供对象关系映射能力。开发者只需定义实体类和继承 JpaRepository 的接口，即可获得完整的 CRUD 操作能力，同时支持方法名推导查询和 @Query 注解等灵活查询方式。

MySQL 8 作为关系型数据库，具备成熟的事务支持、索引优化和 JSON 字段能力，能够稳定支撑本系统用户、房源、预约、订单、消息、工单等多实体之间的关联存储与查询，并满足业务操作的事务一致性要求。

### 2.6 其他辅助技术

**BCrypt 密码加密：** 系统使用 BCrypt 哈希算法对密码进行加密存储，BCrypt 内置随机盐值，能有效防止彩虹表攻击，提高账户安全性。

**@google/model-viewer：** 前端集成了 Google 开源的 Web Component 组件，支持在浏览器中直接渲染 GLB/GLTF 格式的三维模型，用于房源详情页的 3D 看房功能展示。

**LightGBM 推荐增强：** 系统在推荐模块中预留了离线机器学习模型结果导入接口，支持将 LightGBM 等梯度提升模型的预测评分导入数据库，与在线规则推荐分数加权融合。

**文件上传服务：** 系统通过 FileUploadController 提供图片和模型文件的上传接口，文件存储于本地 uploads 目录，并通过 Spring MVC 静态资源映射提供访问，满足房源图片、全景图和 3D 模型的上传与展示需求。

## 第三章 系统需求分析

### 3.1 可行性分析

#### 3.1.1 技术可行性

本文所采用的前后端技术栈均经过工程验证，成熟度较高。前端 Vue3、Vite 和 Element Plus 在大量中小型管理系统中有广泛应用；后端 Spring Boot 3、Spring Security 6 与 Spring Data JPA 均具备完整的官方文档与成熟的生态支持；数据库 MySQL 8 在事务处理和索引优化等方面能满足系统要求。因此，从技术选型上看，本系统具备充分的技术可行性。

#### 3.1.2 经济可行性

本系统开发所依赖的全部工具和框架均为开源免费软件，包括 JDK 17、Node.js、MySQL Community Edition 及各前后端框架，无需购买商业中间件或付费服务。开发环境可在普通个人电脑上完整搭建，符合学生毕业设计的资源条件。

#### 3.1.3 操作可行性

系统面向普通用户、经纪人和管理员三类角色设计，在界面交互上遵循简洁直观的原则，依托 Element Plus 组件库保证 UI 的一致性和易用性。普通用户可以通过首页、列表页和详情页完成找房、收藏、咨询和预约操作；经纪人可通过专属工作台管理房源；管理员可在后台完成房源审核与数据统计。整体操作流程符合用户习惯，具备良好的可操作性。

### 3.2 业务角色分析

系统主要包含三类业务角色，角色之间通过统一的身份认证机制进行区分与权限隔离。

**普通用户（USER）** 是平台的核心服务对象，其主要任务是浏览房源、筛选目标房屋、与经纪人沟通、预约看房并跟踪后续流程。普通用户还可以发布找房需求、获取个性化推荐、提交评价和售后工单。

**经纪人（AGENT）** 负责房源发布、房源编辑、预约处理、排班设置和部分工单处理，是平台业务执行的核心节点。经纪人通过工作台查看自己名下的房源状态、预约安排和服务评价。

**管理员（ADMIN）** 负责平台治理与数据管理工作，包括房源审核、用户账号管理、评论合规审查、业务数据统计，以及推荐训练数据导出与模型预测结果导入等运营操作。

### 3.3 功能需求分析

#### 3.3.1 用户侧功能需求

普通用户的功能需求涵盖以下方面：账户管理（注册、登录、密码找回与个人信息设置）；房源浏览（列表筛选、详情查看，含基本信息、图片、全景图、3D 模型）；交互记录（收藏、浏览历史，为推荐提供行为数据）；咨询与需求（在线发送站内消息、发布找房需求）；预约与支付（选择看房时间发起预约、支付意向金、查看预约进度时间线）；提醒与服务（订阅价格提醒、提交工单、发表评价）。

#### 3.3.2 经纪人侧功能需求

经纪人的功能需求包括：房源维护（发布、编辑、上下架，含基础信息及扩展资源）；预约管理（查看预约申请、审批或拒绝、配置可预约时间段）；工单处理（查看工单、填写处理备注、更新工单状态）；数据看板（查看房源曝光、收藏、咨询、预约和支付转化等统计指标）。

#### 3.3.3 管理员侧功能需求

管理员的功能需求包括：用户管理（查看全部用户，启用或禁用账号）；房源审核（对新发布房源进行合规审核，修改状态）；评论管理（查看全部评价，删除不合规内容）；统计分析（查看全平台用户活跃数据、房源状态分布、订单支付转化和趋势报表）；推荐数据管理（导出用户交互数据、导入模型预测结果）。

### 3.4 非功能需求分析

**安全性：** 用户密码使用 BCrypt 加密存储；所有敏感接口均需携带有效 JWT 令牌，并根据角色进行权限校验，防止越权访问。

**可用性：** 系统应对关键操作提供明显的成功或失败反馈；页面加载异常时应给出友好的错误提示，而非白屏崩溃。

**性能：** 核心接口（房源列表查询、用户登录等）的响应时间应控制在 1 秒以内；数据库查询应对高频字段建立索引。

**可维护性：** 后端采用 Controller → Service → Repository 三层分离设计，前端采用 views/components/api/store 分目录组织，保证各层职责清晰。

**可扩展性：** 系统应为推荐模型接入、消息推送通道、容器化部署和对象存储替换等扩展需求预留接口与配置空间。

## 第四章 系统概要设计

### 4.1 系统设计原则

为了保证系统具备较好的可维护性和扩展能力，本文在概要设计中遵循以下原则：**前后端分离原则**，前端与后端通过 REST API 进行数据交互，降低页面展示与业务逻辑的耦合度；**分层设计原则**，后端严格按照控制层、服务层、持久层进行分层，各层职责清晰；**单一职责原则**，每个模块只负责一类核心业务，避免模块间逻辑耦合过深；**可扩展原则**，对推荐服务、通知服务等扩展模块保留接入接口，使后续功能升级代价最小。

### 4.2 系统总体架构

系统整体采用 B/S（浏览器/服务器）模式。前端基于 Vue3 + Vite 构建单页应用，通过 Axios 向后端发起 RESTful HTTP 请求；后端以 Spring Boot 为核心框架提供业务接口，通过 Spring Security + JWT 过滤链完成身份认证与权限校验；持久层使用 Spring Data JPA 访问 MySQL 数据库；推荐引擎、统计分析和扩展展示模块建立在核心业务数据基础上运行。

### 5.4 关键模块实现

#### 5.4.1 用户认证与权限控制实现

系统认证模块基于 Spring Security 6 构建，在 SecurityConfig 中配置了无状态 Session、JWT 过滤器注入和各接口的访问权限规则。注册时，系统检查用户名和邮箱是否重复，使用 BCryptPasswordEncoder 对密码加密后保存；登录时通过 AuthenticationManager 校验凭据，认证成功后由 JwtUtils 签发包含用户 ID、用户名和角色的 JWT 令牌；后续请求由 JwtAuthTokenFilter 解析令牌并注入 SecurityContext，实现无状态鉴权。

从实现细节看，认证模块还考虑了演示环境的特殊性。在忘记密码接口中，系统生成验证码并在调试模式下直接返回，便于功能演示；历史示例账号异常时自动恢复启用，提高演示稳定性。认证模块关键代码如图 5-5 所示。

#### 5.4.2 房源管理模块实现

房源管理模块通过 PropertyController 提供房源列表查询（支持分页与多条件筛选）、创建、编辑和状态变更等接口。房源实体不仅包含基础字段（标题、价格、地址、面积、户型），还支持全景图 URL、3D 模型 URL、平面图 URL、标签和软装方案 URL 等扩展字段，为地图找房、3D 看房和软装工作室等功能提供数据支撑。

在更新逻辑中，系统对房源所有者身份进行校验，保证非房源拥有者无法修改数据。当房源价格发生变化时，系统联动触发价格提醒模块，向订阅该房源价格提醒的用户生成站内消息通知，实现价格变动的实时推送。

#### 5.4.3 预约看房模块实现

预约模块通过 AppointmentController 管理预约全生命周期。用户提交预约时，系统首先执行时间冲突校验：查询同一房源、同一时间段内是否已存在 PENDING 或 CONFIRMED 状态的预约，若存在则返回错误提示；校验通过后生成预约记录，并通过 InteractionTrackingService 记录用户与房源之间的预约交互行为，供推荐模型训练使用。

系统还提供预约时间线查询接口，将预约创建、支付订单创建、支付结果回调等事件按时序聚合返回，提升流程透明度。

#### 5.4.4 支付订单模块实现

支付模块通过 PaymentController 管理订单完整生命周期。创建订单时，系统校验用户身份、房源有效性和预约匹配关系，自动估算意向金金额，生成全局唯一订单号和模拟二维码 URL，初始化订单状态为 PENDING。系统实现了完整的支付状态机：PENDING → PAID（支付成功）或 PENDING → FAILED（支付失败，记录原因）。支付成功后生成支付凭证，并联动更新关联预约状态为 CONFIRMED，完成业务双向闭环。支付模块关键代码如图 5-6 所示。

#### 5.4.5 个性化推荐模块实现

推荐模块由 PropertyRecommendationService 负责核心逻辑，采用"规则打分 + 模型分数融合"的两阶段方案。规则打分阶段从标签匹配度、区域匹配度、户型匹配度、预算匹配度、面积匹配度和房源新鲜度六个维度对候选房源评分，加权求和得到规则总分。若系统中存在离线模型（如 LightGBM）输出的推荐预测结果，则将模型分数以可配置权重纳入最终排序。该设计兼顾了冷启动时的可解释性与数据积累后的精度提升，相比简单热门排序具有明显的个性化优势。

#### 5.4.6 统计分析模块实现

统计模块通过 StatsController 面向经纪人和管理员提供差异化的数据看板接口。管理员看板包含全平台用户总量与启用率、房源状态分布、近 7 日新增活跃数据、订单支付转化漏斗等；经纪人看板包含自有房源的曝光、收藏、咨询、预约和支付转化统计，以及服务评价和工单处理效率指标。前端使用 ECharts 将上述数据以折线图、柱状图、饼图和漏斗图等形式可视化呈现。
